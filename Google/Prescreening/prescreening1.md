# 11. What Is RAG?

### Answer

RAG stands for Retrieval-Augmented Generation.

Instead of asking the LLM to answer only from its training knowledge, we retrieve relevant information from an external knowledge source and provide that context to the LLM.

The basic flow is:

**User Question → Retrieval → Relevant Context → LLM → Answer**

RAG is useful when the information is private, domain-specific, frequently changing, or not available in the model's training data.

# 13. What Is the Difference Between RAG and Agentic RAG?

### Answer

In traditional RAG, the flow is mostly fixed:

**Question → Retrieve → Send Context to LLM → Answer**

In agentic RAG, the system has more decision-making capability.

The agent can understand the user's intent, decide whether retrieval is required, choose a knowledge source or tool, perform multiple steps if required, and then generate the final response.

So the main difference is dynamic decision-making and tool orchestration.

# 14. What Is an AI Agent?

### Answer

An AI agent is an LLM-based system that can reason about a task, decide what action is required, use tools, observe the result, and continue until the task is completed.

For example, instead of only answering a question, an agent could retrieve company information, call an API, perform a calculation, and then generate a final answer.

# 39. What Is Prompt Injection?

### Answer

Prompt injection is an attack where a user or malicious content tries to manipulate an LLM into ignoring its intended instructions or performing an unintended action.

For agentic systems, this becomes more important because the model may have access to tools or enterprise data.

Controls can include instruction separation, input and output validation, tool authorization, least privilege, content filtering, and limiting the actions an agent can perform.

# 69. Explain Your RAG Architecture in Simple Terms

### Answer

The user sends a question to the application.

The system analyzes the question and determines whether external knowledge is needed.

If retrieval is needed, the application converts the query into an embedding and searches the vector database for relevant information.

The retrieved content is then added to the model context and sent to the LLM.

The LLM generates the final response based on the retrieved context.

In an agentic architecture, the system can also choose between multiple tools or knowledge sources.

---

# 70. What Is an Embedding?

### Answer

An embedding is a numerical representation of text or another data object.

Semantically similar content produces vectors that are closer in the embedding space.

This allows us to perform semantic similarity search rather than relying only on exact keyword matching.

---

# 71. What Is a Vector Database?

### Answer

A vector database stores embeddings and provides efficient similarity search.

In a RAG system, documents are converted into embeddings and stored in the vector database.

When the user asks a question, the question is also embedded and the system retrieves the most relevant document chunks.

---

# 72. How Would You Improve a Poor RAG System?

### Answer

I would first identify where the problem occurs.

Is the document extraction poor?

Is chunking incorrect?

Are the embeddings suitable?

Is retrieval returning irrelevant documents?

Is the context too large?

Is the prompt unclear?

Is the model hallucinating even with good context?

I would evaluate each stage separately and improve the actual bottleneck rather than changing the LLM immediately.

---

# 73. What Causes Hallucination in an LLM Application?

### Answer

Hallucination can happen because the model generates plausible language rather than guaranteeing factual correctness.

It can also be caused by missing context, poor retrieval, ambiguous prompts, excessive model freedom, or unsupported assumptions.

For enterprise applications, grounding, retrieval quality, validation, constrained tool use, and evaluation are important controls.

---

# 74. How Do You Reduce Hallucination in RAG?

### Answer

I would improve retrieval quality, provide only relevant context, instruct the model to ground answers in the supplied information, and use citations or source references where appropriate.

I would also evaluate the system with known questions and expected answers and monitor unsupported responses.

---

# 75. When Would You NOT Use RAG?

### Answer

I would not use RAG when the task does not require external or private knowledge.

For example, simple text transformation, summarization of user-provided text, or general language generation may not need retrieval.

Adding RAG unnecessarily can increase complexity, latency, and cost.

---

# 76. When Would You Use an Agent Instead of a Normal LLM Chain?

### Answer

I would use an agent when the task requires dynamic decision-making, multiple tools, conditional workflows, or multiple steps.

If the workflow is simple and deterministic, I would prefer a normal chain because it is easier to control, test, and maintain.

The recruiter should feel that you are explaining your actual experience, not reciting an interview script.

For every project answer, remember:

**What was the problem?**

**What did I build?**

**What technologies did I use?**

**What exactly did I do?**

**What was difficult?**

**How did I measure the result?**

That structure will help you handle most recruiter follow-up questions naturally.
